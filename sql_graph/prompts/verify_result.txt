Decide whether the result is plausible as an answer to the question. Flag it only for a concrete reason,
for example:
- The result is empty, zero or NULL although the question implies that matching data exists. A text
  filter (a name, title, etc.) may not match the stored value exactly (letter case, punctuation,
  spelling), so the actual stored values should be looked up first.
- A count or total is impossible given the table sizes (for example more customers than the customers
  table contains), which suggests rows duplicated by a JOIN.
- The query answers a different question than the one asked: wrong entity, wrong grouping level,
  wrong time range, or a comparison against the wrong kind of value.

If none of these applies, mark the result as plausible. Do not flag a result just because it is small,
large or surprising. In `issue`, state the problem and what should be verified, in one or two sentences.
